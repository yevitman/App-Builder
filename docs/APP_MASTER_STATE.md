## 아키텍처 협의안 — 승인 전 제안

### AI 파이프라인
- **모드 A, API 직결:** 제공자 어댑터를 OpenAI/Gemini 공통 인터페이스 뒤에 둔다. 먼저 구조화된 계획(JSON 스키마 검증 포함)을 생성하고 승인 상태가 확인된 뒤에만 단일 HTML 생성/패치를 요청한다. 결과는 별도 후보 스냅샷에 반영하고 런타임 검증 후 활성 버전을 전환한다.
- API 키를 프런트엔드 영구 저장소에 두는 것은 안전하지 않다. 기본안은 세션 메모리에서만 사용하거나, 추후 백엔드 프록시와 서버 비밀 저장소를 두는 것이다. 브라우저 로컬 암호화만으로 안전하다고 간주하지 않는다.
- **모드 B, 외부 AI 브릿지:** 사용자가 버튼을 누르면 현재 프로젝트 맥락을 포함한 프롬프트를 클립보드에 복사하고 새 탭을 연다. 팝업/클립보드 권한 실패를 표시하고 수동 복사·열기 방법을 제공한다. 반환 HTML은 붙여넣기/가져오기 후 미리보기 후보로만 두며 승인·검증·버전 기록 단계를 생략하지 않는다.
- **통합 액션:** AI 연결 여부를 사전에 표시하고, 단일 ‘계획 시작’ 액션이 설정된 모드로 분기한다. 계획 생성 → 계획 확인/승인 → 구현 실행 → 후보 미리보기 → 진단 → 버전 확정의 상태 머신을 사용하며 각 단계에서 취소·오류·재시도 상태를 명확히 표현한다.

### 미리보기 및 앱 화면
- 단일 HTML 산출물을 `iframe srcdoc`에서 실행하는 방향을 제안한다. 샌드박스는 기본적으로 스크립트와 동일 출처 권한을 함께 부여하지 않고, 앱의 API 키·저장소와 분리한다. 불필요한 네트워크 권한은 제한하고 HTML 콘텐츠 보안 정책 및 출처 격리를 검토한다.
- 모바일 `100dvh` 셸에서 홈/프로젝트 허브, 요청·계획 승인, 풀화면 미리보기의 세 화면을 전환한다. 탭 또는 단계 네비게이션을 기본으로 하고, 승인·캡처·수정·롤백은 화면을 가리는 드로어/모달보다 상단 플로팅 바와 하단 시트로 제공한다. 작은 화면에 맞춰 내부 패널만 제한적으로 스크롤한다.
- 화면 캡처는 우선 iframe 내 자체 캡처 또는 브라우저 API 가능성을 조사한다. `html2canvas`는 교차 출처 이미지·iframe 콘텐츠를 완전히 캡처하지 못할 수 있으므로 의존성을 확정하기 전에 검증한다.

### 저장·버전·검증
- 구조화된 프로젝트 메타데이터, HTML 스냅샷, 계획/승인 이력은 용량과 복구 요구가 큰 만큼 IndexedDB를 우선 검토한다. LocalStorage는 작은 설정값에 한정한다. 내보내기/가져오기와 버전 해시 검증을 포함한다.
- 후보 HTML을 검증하기 전에 현재 정상 버전을 바꾸지 않는다. 테스트 결과를 기록하고 통과한 버전만 활성화하며, 이전 정상 스냅샷으로 복구한다.

### 제안 기술 스택 및 결정 게이트
- 저장소에 기존 코드가 확인되지 않은 현재 단계의 후보: React + TypeScript + Vite, Tailwind CSS, IndexedDB. 캡처 라이브러리는 기능/브라우저 검증 후 선택한다.
- 프레임워크·패키지 매니저·테스트 도구는 환경을 더 확인하고 작업자 승인을 받은 뒤 확정한다. 이 제안은 구현 승인이 아니며, 이번 턴에서는 코드 작성을 하지 않았다.
