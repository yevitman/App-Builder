# VibeForge Studio — 프로젝트 마스터 헌법

> 상태: 초기 확정안. 이 문서는 프로젝트의 최상위 제품·아키텍처 규범이다. 구현은 이 헌법을 따라야 하며, 원칙을 바꾸려면 작업자의 명시적 승인을 받아 문서를 먼저 갱신한다.

## 1. 앱 정의

VibeForge Studio는 코딩 지식이 없는 사용자가 스마트폰과 PC에서 자연어로 앱을 기획·생성·승인·검증·버전 관리·내보내기까지 원스톱으로 수행하는 AI 기반 자연어 앱 개발 및 유지보수 플랫폼이다.

## 2. 9대 절대 타협 불가 원칙

1. **노코드 자연어 중심** — 사용자에게 코드 직접 편집을 절대 요구하지 않는다. 내부 구현 세부사항은 자연어 요청과 안전한 제품 UI로 다룬다.
2. **선(先)계획 · 후(後)승인 게이트** — 모든 코드 생성 및 수정은 반드시 `요구사항 분석 ➔ 수정 계획서 작성(변경 대상·이유·기대 효과·위험성) ➔ 사용자 명시적 승인 ➔ 코드 반영 ➔ 실시간 미리보기 ➔ 기능 검증` 절차를 거친다. 승인 없는 임의 수정·삭제·기능 추가를 금지한다.
3. **3자 협업 역할 분리** — 작업자(최종 의사결정 및 승인) ↔ 설계·감리 AI(분석·계획서 작성·코드 검증) ↔ 구현 AI(승인 범위 내 코드 생성·수정)의 책임을 워크플로우에 내장한다. 구현 AI는 승인 범위를 넘어 변경하지 않는다.
4. **기존 기능·데이터 보존 및 Hard Freeze** — 정상 동작 중인 모듈을 훼손하지 않는다. 수정은 덮어쓰기가 아닌 불변 스냅샷 버전으로 누적하고, 검증 완료 기능은 Hard Freeze로 잠근다. 오류 시 이전 정상 버전으로 복구할 수 있어야 한다.
5. **실동작 우선 검증 (No Fake UI)** — 모양만 있는 더미 버튼이나 미구현 핸들러를 완료로 보고하지 않는다. 격리된 샌드박스 런타임에서 실제 이벤트·상태·렌더링을 확인하고 기능 진단을 통과해야 완료로 인정한다.
6. **모바일 퍼스트 & 노스크롤 뷰포트 (`100dvh`)** — 스마트폰 세로 화면을 최우선으로 설계한다. 앱 셸은 `100dvh`와 `overflow: hidden`을 기준으로 전체 페이지의 가로·세로 스크롤 밀림이 없는 구조를 유지한다. 모든 버튼과 라벨은 한 줄(`whitespace-nowrap`)을 우선하고, 심플���고 컬러풀한 시각적 위계를 갖춘다. 작은 화면에서도 핵심 콘텐츠가 가려지지 않도록 내부 영역의 스크롤 사용은 명시적으로 설계한다.
7. **다중 프로젝트 독립성 & 맥락 영구 보존** — 여러 앱 프로젝트를 독립 관리한다. 프로젝트별 헌법·아키텍처·최신 정상 버전·완료/미완료 작업·Hard Freeze 목록·수정 이력·다음 단계를 영구 저장하여 세션 변경 후에도 이어갈 수 있어야 한다.
8. **보안 & 캐시 무결성 (Zero-Stale-Cache)** — API 키 등 인증정보를 화면에 평문 노출하거나 승인 없이 외부 전송하지 않는다. 빈 `catch {}` 블록과 런타임 오류를 숨기는 가짜 기본값(`|| 0`, `?? ''`)을 금지한다. 버전 해시 불일치 시 오래된 캐시를 폐기하고 최신 버전을 강제로 적용한다.
9. **수정 전 포렌식 분석 & 대안 역제안** — 기능 추가나 오류 수정 요청 시 즉시 코드를 고치지 않는다. 관련 코드와 런타임 로그를 분석하고 원인 및 더 나은 아키텍처 대안을 제시한 뒤 승인을 받아 실행한다.

## 3. 제품 워크플로우 기준

기본 흐름은 자연어 요구사항 입력 → 분석 및 변경 계획 → 작업자 승인 → 구현 → 실시간 미리보기 → 실제 기능 검증 → 불변 버전 기록 및 복구/내보내기다. 계획 단계와 승인 상태는 분명히 표시하며 승인 전에는 대상 프로젝트를 변경하지 않는다.

결과물은 우선 외부 빌드 서버 없이 실행 가능한 단일 HTML(HTML·CSS·JavaScript 통합)을 목표로 한다. 미리보기는 `iframe`의 `srcdoc` 기반 격리 샌드박스를 고려하되, 생성 코드의 권한은 최소화하고 앱 데이터·인증정보와 분리한다.

## 4. 보안·저장 원칙 보충

브라우저에 저장된 API 키는 같은 기기에서 실행되는 악성 스크립트로부터 안전하다고 간주할 수 없다. 클라이언트 암호화만으로 저장 키를 안전하게 보호한다고 주장하지 않는다. 우선 권장안은 사용자 제공 키를 세션 중 메모리에서만 사용하거나, 별도 백엔드 프록시의 비밀 저장소를 사용하고 명시적으로 승인된 목적지로만 전송하는 것이다. 영구 로컬 저장은 위험과 선택지를 설명하고 별도 동의를 받기 전에는 기본값으로 삼지 않는다.

외부 AI 브릿지는 사용자가 직접 누르는 동작에서 프롬프트 복사와 새 창 열기를 시도한다. 브라우저 권한·팝업 차단으로 실패할 수 있으므로 복사/열기 상태를 확인하고 수동 대안을 제공한다. 외부 제공자에 전달될 데이터 범위를 사전에 알린다.

## 5. 변경 관리

- 본 헌법의 원칙을 구현 세부사항보다 우선 적용한다.
- 요구사항, 계획, 승인 기록, 검증 결과, 스냅샷 식별자를 프로젝트별로 남긴다.
- 위험한 권한(예: 네트워크, 파일, 저장소)은 필요한 경우에만 좁게 허용한다.
- 완료 보고에는 실제 수행한 검증과 남은 제약을 구분해 적는다.
